# Local results — 2026-08-31

These are redacted aggregate results from one host. Raw private prompts,
graders, worker databases, and production receipts are intentionally excluded.
The raw quality artifact also contained a stale `capacity_only` metadata label,
so it is not republished as if it were a clean public benchmark record.

## Host and accepted profile

- GPU: one NVIDIA RTX PRO 6000 Blackwell, 96 GiB, SM120
- Parallelism: TP1; PLE embeddings offloaded to CPU
- Context and token pool: 131,072
- Weights: separately supplied Qwen3.8 Flash-Next NVFP4 candidate
- KV cache: FP8 E4M3
- Speculation: NEXTN, 3 steps, top-k 1, 4 draft tokens
- Reasoning: enabled, `medium`, preserved
- Output cap: 8,192; temperature: 0 in the coding campaign

## Comparative result

| Measure | Flash-Next profile | `worker-36` control | Difference |
|---|---:|---:|---:|
| Matched warm-worker interval | 22.34 s | 28.70 s | 22.2% lower |
| Campaign seconds per clean task¹ | 32.111 s | 40.784 s | 21.3% lower |
| Hidden-clean workers | 9/9 | 9/9 | tied |
| Hidden score | 100 each | 100 each | tied |

¹ Corroborating rather than like-for-like timing: the Flash campaign used the
`run_arm` controller with 15-second polling, while C1 used a custom controller
with 5-second polling. The active worker timestamps above are the clean direct
comparison and should lead any performance claim.

“Seconds per clean task” was wall time divided by clean rate. A clean worker
had to complete, pass public checks, receive the maximum private hidden score,
produce a real scoped commit, preserve reasoning, and stay inside the output
cap. This harness is not public or independently reproduced, so the figures
support a local deployment decision rather than a universal ranking.

## Production acceptance

- Fresh acceptance scout: 38/38 private grading points
- Exact prefill probes: 65,536 and 120,000 prompt tokens
- Soak: 1,948 requests; 0 failures, OOMs, or zombie requests
- Warmed VRAM movement during the final soak: +2 MiB
- Supervised lifecycle: cold start, controlled restart, distinct container/PID,
  readiness gates after each start, and resource release/restore checks

## Honest conclusion

The profile was faster than the local `worker-36` control while tying it on the
tested quality gates. This does not establish that it is better on other tasks,
faster on other hardware, or the fastest deployment in the world.
